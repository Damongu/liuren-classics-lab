# 教学流程复盘

这份笔记记录六壬伴读的实际教学流程。它不是固定教条：每轮结束后根据学习效果复盘。
agent 可以自动分析并提出优化建议，但**未经用户明确同意，不得修改当前流程**。批准后的
改版必须保留旧版本、批准日期、修改理由和验证结果。

## 当前流程

```text
开场简报（retro.py --brief）
→ 读《六壬大全》当前条目
→ 第一轮四拍
→ Terminal 单项练习
→ 错题定位与第二轮四拍
→ 迁移思考
→ 白话复述验收
→ 最终过关
→ 1/3/7/21 天原题复现
→ 收尾复盘（retro.py --close）→ 提案成稿 → 用户批准
```

全程一旦出现摩擦，agent 当场用 `signal_log.py add` 打点，不攒到收尾靠回忆。

### 1. 开场简报

开课前先执行，再读书：

```bash
python3 tools/retro.py --brief
python3 tools/signal_log.py open --topic 本节主题
```

简报汇总四项，逐项处理：建议内容与各专项状态、到期与逾期复现、上轮未处理的摩擦信号、
等待确认的提案（挂满 7 天的当场请用户表态）。简报不替代读书，仍要读：

- [[阅读路线图]]：现在处于哪个学习阶段。
- [[训练记录]]：程序题练到哪里、正确率多少。
- [[错题队列]]：有哪些原题待复现。
- [[学习画像]]：当前稳定强项、薄弱项和常见错误模式。
- [[教学互动日志]]：上一节课哪里不顺。

然后直接说明今天学哪一节、为什么先学这一节。

### 2. 以《六壬大全》为主线

先读《六壬大全》当前条目的原文、注文和课图，再解释概念。唐宋材料用于校核《大全》
所载规则能否追到宋代，不反过来跳过《大全》直接组织课程。

### 3. 第一轮四拍

1. **解释**：先给可执行步骤，再讲原理；首次术语用禄命法作桥。
2. **佐证**：列唐宋原文，检查校记、传抄方向、污染情况，并标证据等级；找不到就写
   “无宋据”。
3. **理解**：先让学习者复述或推演，不先公布完整答案。
4. **质疑**：主动查反例、例外、底本矛盾和后世附会，说明证据稳在哪里、弱在哪里。

### 4. Terminal 单项练习

只练刚学完的概念，不混入尚未教学的内容。程序负责出题和判分，agent 不人工改分。

```bash
python tools/tutor.py --level 1 --topic 遁干
```

近 12 题正确率达到 85%，只叫“练习达标”，还不算最终过关。

### 5. 错题定位与第二轮四拍

错题先定位具体断点，例如没有先定旬首、寄宫记错、局数数反、涉害深浅数错。涉及盘局
必须调用排盘器，以输出中的 `reason` 对照推导。若答案属于另一种文献口径，不判作单纯
错误，而是并列两说。

定位后只针对错点重新走完整四拍，不把整节原样重讲。

### 6. 迁移思考

换条件、找反例或讨论证据边界，检查掌握的是规则而不是某道题的答案。这里不追求题量，
只追求能否说明“条件改变后，哪一步会变、哪一步不变”。

### 7. 白话复述验收

学习者脱离原文，用自己的话把概念讲给一个六壬零基础、但懂基本干支五行的“小白”。
复述至少要说明：

- 解决什么问题；
- 输入是什么；
- 按什么顺序操作；
- 最后得到什么；
- 最容易错在哪里；
- 规则适用到哪里，哪里不能乱用。

agent 此时只按实际听到的内容理解，不替学习者补步骤或润色答案。听不懂时一次只追问
一个关键缺口。小白能够独立照着做，才算验收通过。

### 8. 最终过关

必须同时满足：

1. 程序练习达标；
2. 白话复述验收通过。

验收通过后由 agent 运行：

```bash
python tools/tutor.py --teachback-pass N
```

程序题达标但复述未过时，状态只记“待复述”。复现再次出错，会撤销复述通过状态。

### 9. 间隔复现

按 1／3／7／21 天重问原错题，不用相似题替代。连续答对两次才出错题队列；再次答错则
回到错点四拍和白话复述验收。

### 10. 收尾复盘（由程序执行，不靠自觉）

结束回复前必须执行：

```bash
python3 tools/signal_log.py close
python3 tools/retro.py --close
```

`retro.py` 按写死的阈值跑十条规则（`--rules` 可列出全部阈值），命中即把提案写成稿，
状态为 `草案·待确认`。agent 随后必须在对话里讲清每条提案的证据、建议、收益、风险和
回退，请用户表态，再执行 `--approve` / `--reject` / `--defer`；实施完毕执行
`--implemented`。零命中时只说一句“本轮无异常”，不得编造建议。

**为什么改成程序：** v1.2 把审计写进本页与 `AGENTS.md` 后，实际仍然是用户先发现问题、
再由 agent 补写提案。原因是结构性的，不是态度问题——
① 七项检查中有一半依赖 agent 对刚结束的对话的主观回忆，而会话一关这段记忆即消失，
只有用户还记得；② “结束回复前请自查”是纯文字义务，没有工具锚点，长对话末尾必被跳过；
③ 触发条件没有数字，“错题是否被重复堆积”多少条算堆积未写死，就永远可以判定无异常。
现在这三点分别由 `signal_log.py` 的即时打点、`retro.py` 的必跑命令、`TH` 里的死阈值补上。

审计仍只负责发现问题和成稿，**无权修改流程**。原七项检查内容保留如下：

每次教学、训练、错题讲解或复现结束后，agent 在结束回复前检查：

- 题量、统计窗口和达标阈值是否相互一致；
- 教学、出题、统计和通关是否处于同一粒度；
- 旧制成绩是否混入新制门槛；
- 错题是否由少数相同原因重复堆积；
- 程序成绩、白话复述和间隔复现是否互相矛盾；
- 是否出现应该用图表却持续只用文字的内容；
- 是否出现新的操作摩擦、歧义或无来源结论。

没有异常时不额外打扰。发现有数据证据的问题时，当场向用户提出完整建议，并同步写入
本页“待审批建议”。审计只负责发现和建议，不能绕过审批修改流程。

## 什么时候配图

- **应该配图**：天地盘旋转、四课上下神、三传取用路径、涉害层数、贵人顺逆。
- **优先用表**：寄宫、旬空、旬遁等固定对应关系。
- 原书图必须标书名和页码，并提醒回原书影核对。
- 重绘图必须标“重绘示意，不作证据”，不能冒充原书证据。
- 图片只解决空间关系或流程关系，不作装饰。

## 流程变更审批

### 可以自动更新

- 训练题数、正确率和练习状态；
- 错题、复现日期和连续答对次数；
- 学习画像中的强项、薄弱项、错误模式和证据；
- 按现行规则计算的复习日期。

### 必须先征得同意

- 改变教学步骤或四拍顺序；
- 改变出题范围、题型混合方式或练习阈值；
- 改变白话复述和最终过关标准；
- 改变课程先后顺序；
- 修改训练器行为或本页“当前流程”。

### 建议必须包含

1. **现状证据**：哪些记录说明流程有问题；
2. **修改建议**：具体改哪一步；
3. **预期收益**：准备解决什么；
4. **风险**：可能带来什么副作用；
5. **回退办法**：效果不好怎样恢复。

用户没有明确说“同意”“按此修改”或同等意思时，建议只能停留在待审批区。

     `日干 → 寄宫 → 寄宫上神 → 第一课`。

     的循环依赖。
- **预期收益**：
  - 初学者先有盘面对象，再学局部表格，不会靠追问倒序补术语。
  - 教学、训练和白话复述处于同一粒度。
  - 保留《六壬大全》条目主线，同时给零基础学习者增加必要的最小盘面框架。
- **潜在风险**：
  - “式盘最小模型”并非《六壬大全》的独立条目，若展开过多会变成脱离原书另起课程。

  - 最小模型严格限制为一张图和四句定义，不讲三传、天将及断法。

  - 保留原训练关卡编号和历史成绩，不修改判分算法。

### P-002｜限定专项练习题量并按概念分别验收

- **状态**：已批准、已实施
- **提出日期**：2026-09-08
- **批准日期**：2026-09-08
- **现状证据**：
  - `tutor.py --n` 当前默认 10 题，也允许任意题量，没有专项练习的最低数和单轮上限。
  - 通关统计却取最近 12 题且要求正确率不低于 85%，默认一轮 10 题天然不足以达标。
  - 关卡 1 的寄宫、旬空、遁干共用一条成绩记录；只反复练某一专项，也可能把整关成绩
    推高，不能证明另外两个专项已经掌握。
- **修改建议**：
  1. 每个专项一轮固定 12 题，85% 按整数落实为至少 11/12。
  2. 一轮未达标就停止继续刷题，回到 agent 做错题归因和针对性四拍；讲解后再开新一轮。
  3. 每个专项分别记录正确率、白话复述和复现状态。
  4. 同一关的全部专项都达标后，再做 12 题混合验收。
  5. 混合验收达标且整关白话复述通过，才算最终过关。
- **预期收益**：
  - 题量与“最近 12 题”的统计窗口一致。
  - 防止靠重复刷一个强项掩盖另一个薄弱项。
  - 一轮结束点明确，错误多时及时回到教学，而不是机械加题。
- **潜在风险**：
  - 每个概念都做 12 题会增加总题量。
  - 某些简单概念可能在第 6 题后已经稳定，固定 12 题略显重复。
  - 状态结构需要从“按关卡”扩展为“关卡内按专项”，旧记录要兼容迁移。
- **回退办法**：
  - 保留现有按关卡的历史记录，不删除旧成绩。
  - 新增专项统计字段；若效果不好，可停用专项门槛并继续使用原来的关卡总成绩。
- **实施结果**：
  - 关卡 1 的寄宫、旬空、遁干各自固定 12 题，至少答对 11 题。
  - 各专项分别保存成绩和白话复述状态。
  - 三个专项全部通过后，才开放 12 题混合验收。
  - 旧制 19 条关卡总历史原样保留，不冒充任何专项成绩。

### P-003｜按错误原因管理薄弱训练与错题淘汰

- **状态**：已批准、已实施
- **提出日期**：2026-09-08
- **批准日期**：2026-09-08
- **现状证据**：
  - 错题越积越多后，逐题等权复现会让同一种错误反复占据队列。
  - 当前三道旬遁错题发生在“先考后教”的旧流程下，能说明当时不会，但不宜永久作为
    新流程下的能力证据。
  - 有些错误来自输入格式、有效的另一口径或失效题目，继续复习不会提高规则理解。
- **修改建议**：
  1. 错题先自动进入“待归因”，再由 agent 标记错误原因。
  2. 按原因聚类，而不是按题目数量衡量薄弱程度。
  3. 真正的概念错误和操作步骤错误进入薄弱专项；每个原因保留少量代表题和原错题。
  4. 教学前误测、纯输入错误、有效另一说、题目失效、重复过量题退出活跃队列，但移入
     归档，保留原答案、原因和退出日期，不物理删除。
  5. 薄弱专项先做 3～5 道变式，连续两次正确后停止即时加题；原题仍按 1／3／7／21 天
     复现，用来检查是否真正保持。
  6. 队列按“错误原因”设优先级：反复出现的规则断点优先，偶发笔误靠后。
- **建议的错误分类**：
  - `概念缺失`：不知道规则或术语；
  - `步骤遗漏`：知道规则但跳过关键步骤；
  - `辨析错误`：混淆两条规则或适用边界；
  - `计算失误`：步骤正确但数位、顺逆或计数错误；
  - `输入失误`：输入法或格式造成，理解本身正确；
  - `另一口径`：答案有文献依据，不作普通错题；
  - `教学前基线`：在正式教学前答错，只作起点记录；
  - `题目失效`：题干、答案或规则版本有问题。
- **当前三题的建议处理**：
  - 暂标 `教学前基线 + 步骤遗漏`；
  - 保留在历史档案，不直接计入新制专项成绩；
  - 仍按原题复现一次；若新制教学后答对，则退出活跃队列，若仍错则转为正式薄弱项。
- **预期收益**：
  - 队列不会被同类旧题淹没；
  - 薄弱训练针对错误原因，而不是机械重做所有题；
  - 旧记录仍可审计，不会因“清理”而丢失学习轨迹。
- **潜在风险**：
  - 错误归因需要 agent 判断，可能存在误分类；
  - 过早归档偶发错误，可能漏掉尚未稳定的知识点。
- **回退办法**：
  - 所有退出题只归档不删除，可随时恢复到活跃队列；
  - 保留现有逐题复现数据结构，分类层失效时仍可按原题复习。
- **实施结果**：
  - 新错题默认进入“待归因”；支持按编号归因或归档。
  - 活跃错题与归档错题分开显示，归档保留完整审计记录。
  - 支持按错误原因做 3～5 道变式训练；至少 3 道且连续答对两道后停止。
  - 薄弱变式不计入正式专项成绩，也不向逐题错题队列继续堆积。
  - 当前三道旬遁旧错题已标记为 `教学前基线＋步骤遗漏`，各保留一次正式复现机会。
  - 基线题复现答对即归档；仍错则转为正式“步骤遗漏”薄弱项。

### P-004｜每轮结束执行流程一致性审计

- **状态**：已批准、已实施
- **提出日期**：2026-09-08
- **批准日期**：2026-09-08
- **触发原因**：专项题量、通关窗口和错题膨胀问题均由用户追问后才发现，agent 没有按
  “主动提出建议”的约定提前报告。
- **现状证据**：
  - 旧制默认 10 题，通关却读取最近 12 题，两项配置互相冲突。
  - 旧制按关卡汇总成绩，却允许按专项刷题，统计粒度与通关粒度不一致。
  - 错题只有逐题队列，没有按错误原因聚类和退出机制。
- **修改建议**：每轮教学或训练结束后，agent 自动执行一次只读审计，检查：
  1. 默认题量、统计窗口和达标阈值是否一致；
  2. 教学粒度、出题粒度、统计粒度和通关粒度是否一致；
  3. 旧制数据是否被误算入新制成绩；
  4. 错题数量是否由少数错误原因重复堆积；
  5. 是否出现“程序显示通过，但白话复述或复现未通过”；
  6. 是否有应配图却持续依靠文字讲解的内容。
- **输出方式**：没有异常时不打扰用户；发现异常时，在当前对话主动提交包含证据、建议、
  收益、风险和回退办法的报告，并同步写入“待审批建议”。
- **预期收益**：把流程问题从“用户使用后发现”提前到“每轮结束主动检查”。
- **潜在风险**：检查过密可能产生低价值建议；因此只报告有数据证据的冲突，不报告纯猜测。
- **回退办法**：停用自动审计，恢复为用户提出问题后再复盘；历史审计结果仍保留。
- **实施结果**：
  - 已加入“当前流程”第 10 步，并写入 `AGENTS.md` 强制规则。
  - 每轮结束前执行七项只读检查；有异常就在当前对话主动提示并写入待审批区。
  - 无异常不额外打扰；审计本身无权修改流程。

## 复盘问题

每轮结束后只检查六件事：

1. 是否在教学前就出了题？
2. 题目是否混入尚未学过的概念？
3. 错题是否定位到具体步骤？
4. 唐宋证据是否分级并检查污染？
5. 白话复述是否由学习者自己完成？
6. 图片是否真的帮助理解，而不是装饰？
