# 导读流程·方案（已实施）

用户 2026-09-09 逐项答复六个决策点后回「照办」，本方案全部落地：`AGENTS.md` 第 2.9 节、
[[教学流程复盘]] 的 2a／2b／2c、`tools/guide.py`、`导读不足`／`导读超时` 两个信号、
R12–R14 三条规则、`selfcheck.py` 第 8 项检查均已生效。落地差异与实测数据见第十二、
十三两节。

## 一、为什么要加导读

用户反馈「导读过程不够详细」。核查项目后确认：**这不是执行偏差，是规格空缺**。

- 全项目检索「导读」零命中，没有任何一处定义过导读环节。
- [[教学流程复盘]] 当前流程第 2 步只有一句话：「先读《六壬大全》当前条目的原文、注文和
  课图，再解释概念」。除此之外没有任何可检查的动作。
- 于是每节课的读书环节完全靠 agent 临场决定讲多少，节与节之间不一致，也无法复盘。

真正被漏掉的信息，是四拍第一拍「解释」结构上装不下的那部分：

| 缺口 | 具体表现 |
| :--- | :--- |
| 原文定位 | 现在讲的这几句在原书第几册第几篇第几页，讲解与原文哪一行对应，无法自查 |
| 文本身份 | 哪些是明本原刻、哪些在今注剥离区、哪些是今人补入（如总钤），读者分不清 |
| 切分与读法 | 口诀 33 字里哪几字是规则、哪几字是凑韵；课体 2800 字里哪几段现在该读 |
| 推进关系 | 能力序打乱了书序，跳读之后不知道这一条接在上一节的哪个接口上 |
| 跳过说明 | 本节故意不读什么、为什么不读、什么时候回来读，从来没有交代 |

## 二、导读是什么，不是什么

**导读 = 进入原文之前的地图与读法说明。**只做定位、切分和读法交代，不讲规则原理。

| | 归导读 | 归第一拍「解释」 |
| :--- | :--- | :--- |
| 内容 | 这段文字是什么、在哪、怎么读、先读哪块 | 这条规则怎么操作、为什么这样操作 |
| 产出 | 一张读法地图 + 待答问题清单 | 可执行步骤 + 排盘器实例 |
| 禁止 | 禁止提前给出规则结论和待答问题的答案 | 禁止跳过原文直接给步骤 |

这条边界是本方案的核心约束。导读一旦开始讲原理，就会吞掉整节课，并让第三拍的主动
回想失效（答案已经在导读里说过了）。

## 三、导读固定结构（七件套）

| # | 件 | 内容 | 档位要求 |
| :---: | :--- | :--- | :--- |
| 1 | 坐标 | 册／篇／节／原书页；在零基础课序里的课序；上一节完成了什么，本条接哪个接口 | 必给 |
| 2 | 文本体检 | 正文字数；有无今注剥离区；有无盘；是否今人补入；异体字、疑难字、句读风险点 | 必给 |
| 3 | 切块与读法 | 把原文切成若干块，逐块标注性质：规则／例外／修辞凑韵／断语／象辞／课例；标明本节精读哪块、略读哪块、暂时跳过哪块 | 必给 |
| 4 | 生词护栏 | 本条出现但尚未教学的术语，明确「本节只当名词记住，不展开」 | 必给 |
| 5 | 待答问题 | 读完应能回答的 2–3 个问题，只摆问题不给答案 | 必给 |
| 6 | 冲突预警 | 同一规则在《大全》别处另有说法，或与已学内容表面矛盾，先挂号，留到第二拍佐证处理 | B、C 档必给 |
| 7 | 阅读预算 | 本条精读预计用时；导读本身的时间上限 | B、C 档必给 |

跳过必须写原因和回收时点，不允许只写「本节不读」。

## 四、按正文净字数分三档（修正：不按类型）

初稿按 `类型` 判档，实测后作废。对 257 条《六壬大全》条目统计正文净字数（剔除今注
剥离区与盘），结果与类型并不对应：

| 档 | 判据（正文净字数） | 实际条数 | 主要类型分布 |
| :---: | :--- | :---: | :--- |
| A | < 200 字 | 26 条 | 毕法条目 14、口诀 10、赋文 1、表钤 1 |
| B | 200–3000 字 | 220 条 | 毕法 71、课体 67、赋文 39、神将 32、神煞 9 |
| C | > 3000 字 | 11 条 | 赋文 4、课体 4、兵占 2、分野 1 |

即：毕法条目里有 14 条不足 200 字，课体里有 67 条落在 B 档。**按类型判档会给短条目
派长导读，也会给长条目派短导读。**因此判据改为正文净字数，`类型` 只用于挑模板措辞
（课体讲分区、赋文讲句读、口诀讲凑韵）。判档由 `guide.py` 自动完成。

| 档 | 导读上限 |
| :---: | :--- |
| A | 5 分钟 / 400 字 |
| B | 10 分钟 / 700 字 |
| C | 15 分钟 / 1000 字，且必须给分区表 |

C 档强制要求分区表：这类条目通常混着定义、象辞、断语、课例、解曰五种文字，阶段 3
只读定义与取用条件，象辞与解曰整段推到阶段 5、6，必须在导读里点明，不能让学习者
以为自己漏读。

导读超上限即视为讲课，当场按 `超时` 打点。

### 件数：全档七件必给，但小条目允许压缩成行

初稿曾提「A 档只做 1、3、5 件」，现改为**七件全档必给**，理由是件数争议被 `guide.py`
消解了：

- 第 2、4、6、7 件由程序自动填。写「无今注、无盘、无冲突」的成本是零，不占课堂时间。
- 真正耗时的只有第 3 件（切块与读法）和第 5 件（待答问题），这两件本来就必给。
- 若允许「无则省」，省略就成了 agent 的判断；漏掉一处真实存在的冲突，事后无法区分是
  「确实没有」还是「忘了写」。全档必给才能被程序校验。

A 档条目可把第 2、4、6、7 件压缩成一行，例如「体检：33 字／无今注／无盘／无同名冲突」。

## 五、导读产出物落在哪（已定：乙，用户 2026-09-09 同意）

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |

导读卡文件名与底本条目对齐，例如
`15-导读/01-第一册 起例/005-涉害法-导读.md`，frontmatter 记 `底本`、`档`、`版本`、
`生成日期`、`回执`（未通过／通过）。

## 六、导读回执（轻验收，不是考试）

导读结束、进入四拍之前，agent 问两句，用户用一两句话回答：

1. 这一条要解决什么问题；
2. 本节先读哪块、先不读哪块。

两问的答案全部在刚讲完的导读里，属于复述型，不考六壬本身；它检查的是导读有没有起作用，
不是检查学习者的能力。

**门槛强度二选一：**

| | 硬门槛 | 软门槛（建议） |
| :--- | :--- | :--- |
| 答不出时 | 不许进四拍，重做导读直到答出 | 只补做第 1 件坐标与第 3 件切块，随后照常进四拍 |
| 好处 | 绝不会稀里糊涂往下走 | 时间可控，不会卡在门口反复重讲 |
| 坏处 | 可能在导读环节循环，挫败感高，单节时长失控 | 当节可能带着模糊往下走 |
| 是否留证据 | 是 | 是，同样打 `导读不足`，连续 2 节不过即触发 R13 拆节 |

建议软门槛：回执答不出，多数情况不是学习者没读懂，而是导读讲散了或这一条本身太大；
这两种病都不该用「重讲一遍」来治。

回执**不计入掌握度，不进错题队列**，也不是通关条件。它只是导读自身的效果检查。

## 七、挂进当前流程的位置

当前第 2 步「读《六壬大全》当前条目」拆成 2a、2b 两步，其余步骤不动：

```text
开场简报（retro.py --brief）
→ 2a 导读（七件套，按档限时）
→ 2b 回执（两问）→ 未通过则只重做坐标与切块
→ 2c 原文精读（按导读划定的精读块逐块读）
→ 第一轮四拍
→ Terminal 单项练习
→ 错题定位与第二轮四拍
→ 迁移思考
→ 白话复述验收
→ 最终过关
→ 1/3/7/21 天原题复现
→ 收尾复盘（retro.py --close）
```

一节 60–90 分钟的时间账（B 档）：导读 10 分钟、精读 10 分钟、四拍 30–40 分钟、
练习与讲解 20 分钟。导读吃掉的时间从「反复回头补上下文」里省回来。

## 八、程序支持：`tools/guide.py`（已定：新增，用户 2026-09-09 同意）

按项目一贯做法，硬结构交程序，判断交 agent。导读七件套里有五件可由程序直接生成。

实际实现的命令（条目名支持模糊匹配，不必写全路径）：

```bash
python3 tools/guide.py --entry 涉害法              # 生成导读卡骨架
python3 tools/guide.py --entry 涉害法 --check      # 缺卡／占位未填／过期，三件一起报
python3 tools/guide.py --entry 涉害法 --force      # 底本改过后按最新底本重生成
python3 tools/guide.py --entry 涉害法 --receipt pass --minutes 4
python3 tools/guide.py --list [--stale]            # 导读卡一览／只列过期
python3 tools/guide.py --index                     # 刷新 [[导读进度]]
python3 tools/guide.py --grades                    # 列三档上限
```

| 件 | 由谁填 | 数据来源 |
| :--- | :--- | :--- |
| 1 坐标 | 程序 | frontmatter 的册／篇／节／页；[[阅读路线图]] 的零基础课序 |
| 2 文本体检 | 程序给量，agent 补字词风险 | 正文净字数、`## 盘`、`## 今注剥离区`、`今注数`、`盘数`、`类型` |
| 3 切块与读法 | agent | 需要判断文本性质，不可自动 |
| 4 生词护栏 | 程序给候选，agent 定稿 | `前置` 字段与 `_tutor_state.json` 已达标专项的差集 |
| 5 待答问题 | agent | 需要判断本节目标 |
| 6 冲突预警 | 程序给线索，agent 定性 | 同名规则在其他条目、唐宋层的出现位置 |
| 7 阅读预算 | 程序 | 由正文净字数判档后推算 |

落地时的两处细节：

- **骨架不是导读**。第 1、3、5 件留 `TODO(agent)` 占位，`--check` 会把仍有占位的卡报为
  「未完成」，`selfcheck.py` 第 8 项也会警告，防止骨架冒充导读。
- **切块粒度随档位变**。A 档连中文逗号一起断，口诀切成上下半句（「涉害行来本家止，」／
  「路逢多克为用取。」）；B／C 档先把原刻断行接回成完整句，再按句末标点断，并把不足
  8 字的碎片并回上一句——否则「象天。」「无。」这类残句会各占一行，把切块表撑成噪音。

配套改动：`selfcheck.py` 第 8 项检查导读卡的底本是否存在、是否仍有占位、是否被底本改动
甩过期、进度索引是否与卡数一致。

## 九、与自我迭代机制挂接

导读质量本身也要能被自动发现，否则又回到「用户先发现问题」。**这三条规则解决的问题
就是：让今天这一轮对话（用户发现 → agent 核查 → 写方案 → 用户拍板）以后自动、
小步地发生，而不必每次重来一遍。**

**新增信号类型**：`导读不足` —— 因原文定位、文本身份、切分或推进关系没交代清楚而
产生的追问、回执失败或读错块；`导读超时` —— 单节导读超出该档时间上限。两者都由
`guide.py --receipt` 自动写入 `signal_log`，不依赖 agent 自觉补打点。

**新增规则（阈值写死）**：

| 规则 | 触发条件 | 起草提案内容 | 抓的病 |
| :--- | :--- | :--- | :--- |
| R12 | 单节 `导读不足` ≥ 2 | 修订该档导读模板，补足失效的那一件 | 模板缺件 |
| R13 | 连续 2 节回执未通过 | 降档或拆节，长条目按段拆成两节 | 条目太大 |
| R14 | 某档导读连续 3 节超时长上限 | 压缩该档件数或上调时间预算，二者取一 | 预算不现实 |

R12 举例：连续追问「这句在原书哪一行」「这段和上一节什么关系」→ 当场两条 `导读不足`
→ 收尾自动起草「本档第 1 件坐标需固定到行级定位」→ 一句同意即改模板。

### 为什么不复用已有的 R4、R5

R4 抓 `卡顿`／`前置缺失`，R5 抓 `重复追问`／`图缺失`，两者针对的都是**讲解阶段**的病，
给出的药是「插入前置节」和「改讲法／配图」。导读的病因不同——定位、切分、文本身份、
推进关系。若混用，追问「这句在原文哪儿」会被 R5 判成「该配图了」，药不对症；而真正
该改的是导读模板。因此必须独立信号类型与独立规则，才能开对药方。

三条规则一律只起草提案，仍须用户批准后才改模板，红线不变。

## 九·五、导读卡是批量预生成还是按节生成

**结论：按节生成，另加一张全局索引。**

数据先摆清：《六壬大全》主线共 **257 条、26.6 万字**（唐宋层另有 610 条，只作佐证，
不需要导读）。批量预生成即一次产出 257 份导读卡。

批量预生成的四个问题：

1. **最关键的两件填不了。**七件里第 3 件切块、第 5 件待答问题必须人判断，批量生成后
   257 份里这两件全是空占位。看起来「有导读」，其实等于没有——比现在更糟，因为
   `selfcheck` 会认为导读已存在，不再报缺。
2. **第 4 件生词护栏是动态的。**它算的是「本条前置」与「你当下已达标专项」的差集。今天
   为阶段 4 条目生成的护栏会写「寄宫只当名词记住」；等你真读到阶段 4，寄宫早已 12/12
   通关，这条护栏变成噪音甚至误导。
3. **第 6 件冲突预警依赖唐宋层入库进度。**现在生成的线索，和半年后又补入《玉门经》
   《毕法赋》校本之后生成的，不是同一份。
4. **vault 噪音与报警失效。**多 257 个半空文件，Obsidian 图谱、搜索、Dataview 全被稀释；
   「导读过期」检查会天天报一大片，报警一旦常态化就等于没有。

按节生成的成本：开课前一条命令、约两秒，五件即时正确（读的是当下的 frontmatter、
当下的训练状态、当下的唐宋层）。一节课只用一条，备好 257 条没有任何收益。

**要全局视角，做的应是索引而不是卡：**`guide.py --index` 生成一张导读进度表
（Dataview），列出每条底本的档位、有无导读卡、导读卡是否比底本旧、回执状态。这样
「全书哪些读过、哪些导读过期」一眼可见，维护成本接近零。

若仍想先看一批，折中方案是只预生成当前阶段（阶段 3 共 17 条），跑完一轮再决定是否扩大。

## 十、红线

导读不得：

1. 提前给出规则结论，或泄露待答问题的答案；
2. 引用尚未教学的概念作为解释前提（只能作名词护栏）；
3. 把今注剥离区、总钤等今人内容当作原刻正文导读；
4. 用重绘图冒充原书课图，或不标页码就引原文；
5. 替代第一拍解释、或占用超过本档时间上限；
6. 因导读补充而改变四拍顺序与任何验收标准。

## 十一、收益、风险、回退

**预期收益**：每节读书环节有固定结构，跳读不再丢上下文；原文与讲解逐块对应，用户
可自查 agent 有没有偷换内容；今人补入内容与明本原刻在入口处即被分开，与取证规则
同向加强；导读缺失、失效、超时都能被程序发现。

**风险**：① 七件套全给可能让节奏变慢，尤其 A 档短条目导读显得头重脚轻（对策：第 2、4、
6、7 件由程序填并压缩成一行）；② 导读写多了会变成变相讲课，损害主动回想（对策：红线
第 1 条 + 档位字数上限）；③ 若批量预生成 257 条导读卡，会产生大量未经验证的模板文本
（对策：按节生成，只做全局索引）。

**回退**：导读卡独立存放于 `15-导读/`，停用只需在流程里删掉 2a、2b 两步，底本、概念卡、
训练记录和成绩全不受影响；已生成的导读卡保留备查。

## 附录：A 档导读样例（涉害法，33 字）

以下为按本方案写出的一份 A 档导读，用于判断颗粒度是否合适。**它只做定位与读法，
四个问题一律不给答案。**

**1 坐标**
第一册 起例｜入手法｜涉害法，原书页 8-8，正文 33 字，类型口诀，阶段 3。
在零基础课序里属第 5 课「九宗门其余规则」。上一节已完成贼克、比用与主干三传；本条接的
接口是「四课有克，但比用也定不出唯一用神」这一分支，不是另起一套起课法。

**2 文本体检**
33 字，四句。无今注剥离区，无盘图，全部为明本原刻。
同名条目另见第六册《涉害课》p260-265，2972 字带 2 盘——那是课体与断语，本节不读。
字词风险：「柔」「刚」是阴日阳日的术语，不是形容词；「复等」指涉害深浅相等，不是「重复」。

**3 切块与读法**

| 块 | 原文 | 性质 | 本节 |
| :---: | :--- | :--- | :--- |
| 1 | 涉害行来本家止 | 规则·路径起止 | 精读 |
| 2 | 路逢多克为用取 | 规则·取用判据 | 精读 |
| 3 | 孟深仲浅季当休 | 规则·深浅判定，且是已知口径分歧点 | 精读并挂号 |
| 4 | 复等柔辰刚日宜 | 例外·打平后的备用规则 | 精读 |

四句全精读，不跳过；本节不读第六册课体与断语，等阶段 4 课体期回收。

**4 生词护栏**
孟仲季：本节只当作「寅申巳亥／子午卯酉／辰戌丑未」三组记住，不展开四时旺衰。
见机、察微等后世名目本条不出现，不提前引入。

**5 待答问题（读完自己答，导读不给答案）**
① 「本家」指盘上哪一格？
② 「深浅」在数的是什么东西的个数？
③ 深浅相等时，凭什么在两者之间决定？

**6 冲突预警**
孟仲季判深浅，是按地盘宫位还是按天盘神数，《大全》此处与唐《太白阴经》卷十玄女式的
表述不一致；排盘器为此留了口径开关。此点留到第二拍佐证处理，导读只挂号。

**7 阅读预算**
A 档：导读 5 分钟内，精读 5 分钟，随后进第一拍。
