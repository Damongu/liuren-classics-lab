# 唐宋层导入指南（本地八部书 → Obsidian）

你手上这批书到位之后，vault 的性质变了：**从"读一本书"变成"多本互校"**。
所以导入不是"把文件拖进来"，而是三件事：**统一形态 → 建立可链接的最小单元 → 挂到对校面板上**。

---

## 一、先定原则：Obsidian 存什么、不存什么

| 放进 vault | 不放进 vault |
| :--- | :--- |
| 纯文本录文（切成篇 / 条 / 法） | PDF、扫描图、影印本（几百 MB，会把索引和同步拖死） |
| 你自己的卡（考据、校读、课例） | 原始抓取的 HTML / JSON 垃圾层 |
| 结构化元信息（frontmatter） | 整部与六壬无关的书（如《武经总要》全书） |

> **原书影另存一个目录**（vault 之外），在书卡里写路径就行。
> Obsidian 只管**可搜索、可链接、可批注**的东西。

## 二、目录结构（导入后长这样）

```
六壬vault/
├── 10-底本/
│   ├── 六壬大全/          ← 阅读主线（257 条，已有）
│   └── 唐宋层/            ← 证据层，新增
│       ├── 太白阴经/
│       │   ├── 00-书卡-太白阴经.md        ← 每书一张，先读这个
│       │   ├── 00-太白阴经目录.md         ← 脚本自动生成
│       │   ├── _导入报告.md               ← 核对字数与漏项
│       │   └── 太白阴经-推四课法.md        ← 条目，可双链引用
│       ├── 占事略决/  景祐六壬神定经/  武经总要/
│       ├── 六壬心镜/  六壬断案/  壬归/
├── 40-考据卡/            ← 一个待验命题 = 一张卡，链向各书条目
├── 50-校读笔记/
│   ├── 对校矩阵-五个判别点.md   ← 主工作面
│   └── 互校污染规则-方法卡.md   ← 引用前必读
└── 70-待查/待查清单.md
```

七张书卡**已经预先写好**，导入前先各读一遍——里面写了每部书的坑、能结掉哪条待查、以及现成的导入命令。

## 三、跑导入

脚本在 `tools/import_tangsong.py`，纯标准库，不装依赖也能跑。

```bash
cd 六壬agent工作区

# ① 先探（不写文件，只看会切出什么）
python3 tools/import_tangsong.py --src ~/六壬书/太白阴经 --book 太白阴经 --dry-run --split-headings

# ② 正式导
python3 tools/import_tangsong.py --src ~/六壬书/太白阴经 --book 太白阴经 \
  --evidence 一手 --dating "唐·约759" --version 十卷本 --risk 无 --split-headings
```

脚本替你处理了三个实际麻烦：

1. **编码**：繁体抓取常是 Big5 / GBK。直接按顺序试会出乱码（gb18030 几乎能"成功"解码任意字节），
   所以脚本把候选编码全解一遍、按中文可读性打分取最优，编码记在 frontmatter 的 `源编码`。
2. **切条**：`--split-headings` 按「卷X / 第X篇 / markdown 标题 / 一、二、」切。
   太碎不利于链接，短于 `--min-chars`（默认 120 字）的段落并入上一条；想每个标题都独立成条就 `--min-chars 0`。
3. **幂等**：已存在的条目**默认跳过**，不会覆盖你写在正文里的批注。要重导才加 `--force`。

**繁简**：装了 opencc 会自动转简体（便于跨书搜索与对校），没装则保留原文并标 `繁简: 未转`。
建议装：`pip install opencc-python-reimplemented`。

> ⚠️ 《武经总要》两个抓取文件夹：**只导后集卷二十一「六壬占法」那部分**。
> 先各跑一次 `--dry-run`，看报告里有无「六壬 / 占法」条目再决定。整部兵书铺进来会把搜索和 Graph 淹掉。

## 四、导入后必做的三步

### 1. 核导入报告
打开每书的 `_导入报告.md`，对三件事：条目数、字数、有没有"空文件跳过"。
抓取工具漏页很常见，**报告里字数明显偏小的条目要回源核**。

### 2. 给《六壬心镜》扫校记
这是唯一有**高危污染**的一部。逐条扫，命中「据《大全》改 / 据某本改正 / 疑 / 脱 / 衍 / 今改 / 今补」的，
在该条 frontmatter 加一行 `污染: true`。

这张污染位置表是所有《心镜》↔《大全》互校的前提。理由见 `[[互校污染规则-方法卡]]`。

### 3. 开始填对校矩阵
打开 `[[对校矩阵-五个判别点]]`，八部书 × 五个探针。
一格一句原文＋卷篇定位，不写解释。**这一步才是知识库真正开始产出的地方。**

## 五、Obsidian 侧怎么配

### 必开（设置项）
- **Files & Links → 新建链接用 Wikilink 格式**，把 `Use Wikilinks` 打开。
- **Files & Links → Automatically update internal links** 打开（改文件名不断链）。
- **Files & Links → Excluded files**：把 `_导入报告` 之类加进去，让它们不参与搜索排名（可选）。

### 建议装的插件（都免费）
| 插件 | 干什么 | 为什么这里需要 |
| :--- | :--- | :--- |
| **Dataview** | 用查询语句列表格 | 把 frontmatter 变成活面板，见下 |
| **Spaced Repetition** 或 **Review** | 间隔重复 | 配合 1/3/7/21 天复现 |
| **Omnisearch** | 更好的全文搜索 | 跨八部书找一句话时明显好过内置 |
| **Templater**（可选） | 模板自动化 | 新建考据卡时自动带 frontmatter |

> 不用装同步插件。Obsidian Sync 要钱，用 **git** 免费搞定（工作区已是 git 仓库，
> 推到私有仓库，手机端用 Working Copy / obsidian-git 拉取）。

### Dataview 面板示例

新建 `00-索引/证据面板.md`，粘进去就能用：

````markdown
## 所有书卡（按证据等级）
```dataview
TABLE 断代 as 断代, 证据等级 as 证据, 理据价值 as 理据, 抄大全风险 as 风险, 导入状态 as 状态
FROM #书卡
SORT 证据等级 ASC
```

## 待核条目（还没回原刻核过的）
```dataview
TABLE 书, 卷篇, 源文件
FROM #底本 AND #唐宋层
WHERE 待核 = true
SORT 书 ASC
```

## 高危：有清校污染标记的条目
```dataview
LIST
FROM #底本
WHERE 污染 = true
```

## 所有未结的考据卡
```dataview
TABLE 命题, 断代, 状态
FROM #考据卡
WHERE 状态 != "已结项"
```
````

这四个查询就是日常入口：**今天读什么、哪些还没核、哪些不能引、哪些命题还开着。**

## 六、双链怎么用才有价值

Graph 好看但没用，**双链的价值在反向链接**。做法：

- 每张考据卡在正方 / 反方证据里**直接链条目**，如 [[太白阴经-推四课法]]。
- 于是打开任一条目，右侧 Backlinks 就会显示"哪些命题正在用我作证"。
- 某条原文一旦被判为讹误或污染，**顺着反向链接就能找到所有受影响的结论**——
  这才是知识库真正防错的地方，比任何标签体系都实用。

命名纪律（保证链接稳定）：
```
条目：<书名>-<卷篇>              例：太白阴经-卷十-元女式
书卡：00-书卡-<书名>
考据卡：<对象>-<命题短语>         例：壬归-分级修正与理据层定位
```

## 七、一句话流程

```
抓取文件夹 → 跑脚本 → 核导入报告 → 扫《心镜》校记 → 填对校矩阵 → 出考据卡 → 改排盘器开关
```

前四步是搬运，第五步才开始出东西。别在搬运上花太多时间——
**矩阵里那两个 ⭐ 格子（涉害俱深、贵人表）填上，比把八部书全部导完更有价值。**
