# Pi内的自动课堂讨论

用户明确要求讲解时自动讨论，并确认要借鉴OpenMAIC的活跃课堂体验。
本轮落实既有“复盘官协调独立书魂”的设计，修正此前只有手动入口的缺口。
主读底本与四拍顺序保持，由程序自动协调其他角色；用户无需充当调度员。

依据：OpenMAIC官方README中的主动课堂讨论与用户随时参与。
来源：https://github.com/THU-MAIC/OpenMAIC 。只借鉴互动方式，不安装或移植其整套平台。

修改：新增liuren_discuss，按关键词检索可用证据，最多请两位他书魂独立补证/质疑，
再请复盘官核阅；主讲在同一Pi会话展示角色发言、共同点与分歧，提出一个理解问题。
首次输入插入隐藏课堂提示。每小节通常一轮、每次用户输入硬上限两轮；用户插话再继续。
子书魂只能读取与验证自己原文，不能递归讨论、写学习记录或保存会话。

收益：主讲持续带读，其他角色主动提边界和反例，用户能插话；单书范围不妨碍课堂互动。
已核讨论引文可在主讲答案中按discussion_id和speaker归属核验，不能靠虚构角色绕过规则。
没有根据或调用失败时直说，不假装多人已经达成共识。

风险：一轮通常增加两个书魂与一次复盘官模型调用；发言数、字数与执行时间有界。
程序验证原句、来源、发言者和授权，不代替文义判断，不能证明多模型发言都正确。
子会话沿用当前Pi模型provider/id及Pi自身凭据环境，不索取或复制用户密钥。
Windows直接执行已安装Pi实际CLI，超时结束对应模型进程，避免外层启动器留下子进程。

回退：在规则中恢复只读检索、不调用讨论工具，即可停用自动讨论；旧训练成绩和底本不受影响。

使用：更新后重新打开一次项目Pi会话，仍运行启动六壬.ps1。直接说：
“从这一节开始带读，必要时请其他书魂加入，遇到分歧让他们讨论，我会插话。”
主读《中黄经》时无需为景祐或武经发言重新启动。主动换主读底本才用-Book。

验证：新增7项模拟测试覆盖选择、独立发言、核阅、证据授权、故障、递归和CLI隔离。
真实Pi加载器检查讨论工具注册、伪造discussion_id拒收与子会话递归拒绝。
真实模型讨论尚须在可用Pi凭据下验收，不能把模拟角色输出当成实际课堂发言。
