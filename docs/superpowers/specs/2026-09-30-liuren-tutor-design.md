## 1. Context & Forcing Function

作者需要系统地学习六壬，手上有九部底本：宋本系六部（《中黄经》《六壬断案》《壬归》《武经总要》《神定经》《六壬心镜》）、唐本系三部（《卜筮书》残卷、《占事略决》《太白阴经》）、明本《六壬大全》。语料版本差异大、术语密集、缺乏系统化白话译注，人工逐字啃书效率极低。

作者已具备起课排盘能力与禄命法功底，缺失的是：宋本原文语感、九宗门与特殊格局识别、断辞组织、宋唐语料层次差异。已有开源项目 `liuren-classics-lab` 提供了成熟的四拍循环、导读七件套、排盘器程序判分、打点自迭代框架，可直接沿用。

**Forcing function**：在保留 `liuren-classics-lab` 全部机制的前提下，加入两项针对作者的定制——**每部底本一个独立 agent 人格（书魂）** 与 **子平法幻觉的 prompt 层约束**——形成可落地的个人向带读教学系统。

## 2. Goals

- 建成可复用的 Obsidian vault，覆盖九部底本 + 大全字典，语料按「宋本主 / 唐本佐证 / 大全字典」三层分区。
- pi coding agent 通过 `--agents-file` 加载书魂档，每部书带读时切换到该书人格；跨书校勘由复盘官协调独立会话。
- 每次带读遵循「解释 → 佐证 → 演练 → 复述」四拍循环；佐证拍产出「宋证 / 唐证 / 无宋据」三态之一。
- 排盘器（Python 纯标准库）对 720 课全枚举，训练题目由排盘器现算标准答案，LLM 不参与判分。
- 打点、规则、提案闭环保留 `liuren-classics-lab` 的 11 种信号与 R1–R14 规则；提案带齐五项。
- 学习路径分六关（L1–L6），跳过纯排盘机械训练关。

## 3. Non-goals

- 不做面向他人的开放平台，单用户单机。
- 不本地跑 LLM，只走 DeepSeek API。
- 不做占卜结果的玄学正确性评判。
- 不清洗子平法语料，不建关键词黑名单，不建子平污染隔离目录。
- 不做「禄命 → 六壬」迁移桥表述——宋壬与禄命一脉相承，直接互文。

## 4. Success Criteria

**结课测**：给出 5 例训练集之外的南宋断案课例，作者独立完成 **起课 → 课体识别 → 三传取用依据 → 断辞组织 → 每步锚回宋本原文出处**。全对 4 例、其余无原则性错误即视为结课。

**MVP 验收**（子项目 A + B，4 周）：《中黄经》一部书跑通完整四拍循环；在 5–10 条子平诱导测试用例上第六条红线全部 reject；书魂 profile 切换机制可稳定复现。

## 5. Constraints & Degrees of Freedom

**固定**：LLM = DeepSeek API；agent = `@earendil-works/pi-coding-agent`；笔记与语料 = Obsidian vault（Markdown + Frontmatter）；宋本主训读、唐本佐证、大全字典。

**可变**：目录名细节、导读档位阈值、关卡题目分布权重、提案规则集扩展。

## 6. Design Overview

三件套架构：

```
Obsidian vault  ── 单一真源，Git 私仓同步
     ↕（相对路径读写）
pi coding agent  ── DeepSeek 后端
   AGENTS.md（系统级） + agents/<书>.md（书魂）
   四拍 + 导读七件套 + 打点 + 规则 + 提案
     ↕（子进程调用，不经 LLM）
liuren-paipan  ── Python 纯标准库，720 课全枚举
   tutor.py / guide.py / retro.py / signal_log.py
```

vault 承载状态，pi 承载 LLM 交互，Python 工具链承载可判定的机械逻辑。三者边界清晰：Python 工具产程序判分与骨架，pi 出解读，vault 存磁盘化产物。

## 7. Detailed Design

### 7.1 Vault 结构

```
六壬vault/
├── 00-索引/         阅读路线图、关卡表、导读进度、复盘
├── 10-底本/
│   ├── 六壬大全/    明本正文（字典用途）
│   └── 唐宋层/      宋本主 6 部 + 唐本佐证 3 部 + 待核残卷
├── 15-导读/         导读卡（按节生成，不批量预生成）
├── 20-概念卡/       九宗门、涉害、别责、毕法……
├── 30-课例/         排盘器落卡 + 南宋断案课例
├── 40-考据卡/       唐→宋差异点
├── 50-校读笔记/     对校矩阵（五个判别点）
├── 60-掌握度/       训练记录、错题队列、教学互动日志
├── 70-待查/         有疑问但无宋据的挂号项
├── 90-禄命辅助/     种子若干（本命/行年/年命上神/禄/马/贵人/天乙/驿马）
│                    可用 `tools/add_lulu_stub.py` 学习中随时增补
└── 99-今注剥离/     清校污染 + 今人补入
```

每条原文 frontmatter 沿用上游中文字段（`书 / 版本 / 卷篇 / 断代 / 证据等级 / 理据价值 / 抄大全风险 / 繁简 / 待核 / 源文件 / tags`），v3 新增：

- `anchor_id`：格式 `<花名>-<卷篇 slugified>-<段序 3 位>`（例 `太白-玄女式-001`）；断案按段拆，同一 md 可出现多个 anchor_id（含内嵌注家段）
- `作者`：书魂花名（`凝神子 / 略决 / 太白 / 心镜 / 景祐 / 武经 / 邵彦和 / 阿甲 / 林景行 / 壬归 / 卜筮残 / 大全查手`）
- `与六壬关系`：**开放集**（甲方案），沿用上游 `build_vault.py` 已写入的细粒度分类（如 `兵占背景 / 同源三式 / 本体规则 / 术语共享·干支分野` 等）；同时接受 v3 补充的粗粒度值 `主体 / 旁证 / 遁甲 / 太乙 / 占候旁证 / N/A / 字典`。checker 只判缺失，不做 enum 校验；Task 4 只补齐缺失不改写已存值。武经/太白全条目保留，按每条实际标注
- `含内嵌注家`：仅《大六壬断案》使用，列出该 md 内除主作者外的段级注家花名

### 7.2 书魂架构（Agent Profile）

采用**花名**作为书魂档命名与 frontmatter `作者` 字段值。花名列表如下（12 档，含《大六壬断案》**一书三魂**）：

| 花名 | 对应底本 |
|---|---|
| `凝神子` | 大六壬五变中黄经·正文 |
| `略决` | 占事略决 |
| `太白` | 神机制敌太白阴经·卷十元女式（含其他篇作占候/旁证） |
| `心镜` | 六壬心镜 / 六壬心镜要 |
| `景祐` | 景祐六壬神定经 |
| `武经` | 武经总要·后集卷二十一「六壬占法」（含遁甲/太乙/占候旁证条目） |
| `邵彦和` | 大六壬断案·南宋原辞 |
| `阿甲` | 大六壬断案·清人爱函按 |
| `林景行` | 大六壬断案·现代今注（缘生谛校注） |
| `壬归` | 壬归（题宋郭子晟） |
| `卜筮残` | 卜筮书·卷第廿三·断简 |
| `大全查手` | 六壬大全（词典管家，只出词条不出解读） |

```
agents/
├── AGENTS.md            # 系统级：四拍、六条红线、旁通发散、工具契约、路由
├── 凝神子.md
├── 略决.md
├── 太白.md
├── 心镜.md
├── 景祐.md
├── 武经.md
├── 邵彦和.md
├── 阿甲.md
├── 林景行.md
├── 壬归.md
├── 卜筮残.md
├── 大全查手.md
└── _system/
    ├── 导读官.md        # 出七件套
    ├── 排盘守卫.md      # 只调 tutor.py / paipan
    └── 复盘官.md        # 跑 retro.py，协调跨书校勘
```

**《大六壬断案》一书三魂**：邵彦和主档承载原辞；阿甲档只处理「爱函按：」段；林景行档只处理「缘生谛：」（今注）段。段级归属由 anchor_id 与 `作者` 字段确定，物理文件不拆。

**每份书魂档必含五段**：

1. **身份**——作者视角、成书年代、版本源流
2. **术语偏好**——该书独用/特义的术语表
3. **句式与文体**——口诀/断案/官修条列，影响解读语气
4. **可引证范围**——本书在四拍·佐证拍里可作为哪一档证据；断案三魂各自的引证等级不同（邵彦和=硬据，阿甲=清校旁证，林景行=今注仅参考）
5. **冲突预警**——与他书同名概念的分歧点清单

**切换机制**：pi 启动时 `--agents-file agents/凝神子.md`。主 `AGENTS.md` 通过 include/reference 被拼进 system prompt；系统级规则与书魂人格是两层拼接，不由 agent 自己混写。跨书校勘由 `_system/复盘官.md` 触发新会话，读多书魂档的「可引证范围」段。**单书魂被诱导跨书发言时须拒绝并挂号 `70-待查/`**。

### 7.3 四拍循环

每条原文或概念的教学单位：

1. **解释**——白话讲清这条讲什么，直接指向原文 anchor_id
2. **佐证**——出四态之一：**宋证**（宋本互证）/ **唐证**（带「⚠️唐本佐证」标签）/ **旁通**（武经/太白里的遁甲/太乙/占候旁证，供发散思考，不作硬证）/ **无宋据**（不许编造）
3. **演练**——调排盘器出一课，作者识别/断辞，程序判分
4. **复述**——作者用自己的话把这条讲一遍，agent 只作提示不代讲；复述过后 `mastery` 升级

### 7.3.1 旁通发散机制（v3 新增）

主线带读遇到相关议题（择日、占候、太乙、遁甲、择时等）时，agent 可**主动检索**《武经》遁甲/太乙/占候旁证条目、《太白》除玄女式外的诸篇，作为**旁通参考**输出。旁通输出必须：

- 用「**旁通**」标签明示，绝不与「宋证/唐证」混淆
- 引用时带原条 anchor_id 与 `与六壬关系` 字段值（例 `武经-遁甲-005 [遁甲]`）
- 不进入 mastery 计分；只入 `70-待查/` 或 `40-考据卡/` 供人肉认领
- 每次带读的旁通条目上限 3 条，避免喧宾夺主

数据基础由本子项目 A（Task 4）建成——所有武经/太白条目按实际标注 `与六壬关系`。行为规则在子项目 B 的 AGENTS.md 里落。

### 7.4 导读七件套（软门槛）

读原文前必须过一遍：①坐标 ②文本体检 ③切块与读法 ④生词护栏 ⑤待答问题 ⑥冲突预警 ⑦阅读预算。

**档位按净字数判**：A < 200 字（≤5 分钟/400 字）；B 200–3000 字（≤10 分钟/700 字）；C > 3000 字（≤15 分钟/1000 字，必须给分区表）。

**回执机制**：进四拍前问两句——「这一条要解决什么问题？本节先读哪块、先不读哪块？」答不出打 `fail`；触发 R13 时降档或拆节。

### 7.5 排盘器（liuren-paipan）

- Python 纯标准库，无 LLM 依赖
- 720 课全枚举（60 干支 × 12 局），40 ms 完成
- 训练题目由排盘器现算标准答案
- 支持涉害深浅、比用格改比和等特殊判定
- 底本课例回归 18 项 + `duanan_cases.json` 164 则南宋课例

### 7.6 关卡

| 关 | 主题 | 通关线 |
|---|---|---|
| 跳过 | 纯排盘机械训练 | 首次全对基线体检即放行 |
| L1 | 课体识别（九宗门） | 近 12 题 ≥ 85%，按课体等概率抽题 |
| L2 | 涉害深浅 + 比用格改比和 + 贵人前后 + 天将吉凶宋本口径 | ≥ 85%；半对◐ 两说并陈 |
| L3 | 返吟伏吟、遥克、别责 | ≥ 85% |
| L4 | 年命上神 + 行年 + 本命在断辞中的角色 | ≥ 85%；每题必带年命信息 |
| L5 | 毕法赋断辞组织 | ≥ 85%；断辞逐句锚回宋本 |
| L6 | 南宋《六壬断案》课例复盘 | ≥ 85%；每例先自断再对底本原断 |

### 7.7 六条红线（AGENTS.md 顶级约束）

1. 证据分级与污染判定（宋本主 / 唐本佐证 / 大全字典 / 清校污染 / 今注剥离）
2. 四拍顺序不可颠倒（解释 → 佐证 → 演练 → 复述）
3. 排盘器判分口径为准，LLM 不参与判分
4. 「宋据优先，没有就写无宋据」，不许编造出处
5. 流程变更须先获作者批准，agent 不自改流程
6. **解释六壬术语时不引入子平法义项作解**；原文或佐证中出现共名词汇（用神 / 命宫 / 纳音 / 大运）时，agent 显式标注「此处取六壬义」并给宋本出处；无出处写「无宋据」。宋壬与禄命一脉相承，可直接互文，不作「迁移」表述

### 7.8 磁盘化文件所有权

| 文件 / 目录 | Owner | 写入协议 |
|---|---|---|
| `60-掌握度/训练记录.md` | tutor.py | append-only，agent 只读 |
| `60-掌握度/错题队列.md` | tutor.py | `<!-- tutor:begin -->` 区自动维护 |
| `60-掌握度/教学互动日志.md` | agent | agent append，复盘官汇总 |
| `signal_log.jsonl` | agent | signal_log.py CLI 敲入 |
| `50-校读笔记/` | 复盘官 | 跨书校勘会话独占写 |
| `15-导读/` | guide.py + 书魂 | guide.py 出骨架，当值书魂填内容 |
| `70-待查/` | agent | 「无宋据」自动挂号，人肉认领 |

## 8. Alternatives

| Approach | 做法 | 为何不选 |
|---|---|---|
| **选中** | fork `liuren-classics-lab` + pi 多 profile 书魂 | —— |
| A2 | 不 fork，纯自建 vault + Cursor/Trae 替代 pi | 放弃已成熟的 tutor.py / guide.py / retro.py 工具链，重复造轮 |
| A3 | Obsidian 插件（Copilot / Text Generator）直跑，不引入 Python 工具链 | 无程序判分，720 课全枚举优势失效，LLM 幻觉不可控 |
| A4 | OpenClaw workbench（真独立 session state） | 引入 Next.js + Postgres 过重，单用户不划算；作为后期升级选项保留 |

## 9. Cross-cutting Concerns

### 9.1 子平幻觉

**约束层在 prompt 与输出后检查，不动语料**。AGENTS.md 第六红线定义共名词汇处理策略；MVP 阶段配 5–10 条子平诱导测试用例，全部 reject 才允许发版。作者复述拍人肉核对是最后一道拦截。

### 9.2 唐宋分层

书魂档「可引证范围」段规定单书魂只能引用什么等级的证据。跨书发言必须由复盘官发起新会话。四拍·佐证拍产出必带三态标签之一。

### 9.3 LLM 幻觉替原文

原文只由 vault 检索注入，agent 只能注释不能重述。写盘前跑原文 hash 校验（若命中「重述原文」则拒收）。

### 9.4 书魂串戏

方案 A（pi 多 profile）的主要风险。缓解：单会话只加载一个书魂档；单书魂被诱导跨书发言须挂号 `70-待查/` 而不是就地作答。

### 9.5 可观测

`signal_log list --days 7` 抽查；连续两节空日志触发人为回炉。R11 变体规则捕获「打点缺失」模式。

## 10. Rollout & Validation

### 10.1 子项目切分

| 子项目 | 交付物 | 范围 | 周期 |
|---|---|---|---|
| A. 语料工程 | 可用 vault | OCR 收敛、三层分区 frontmatter、`--check` 全绿 | 2 周 |
| B. Agent 骨架 | 系统 prompt + 首个书魂 | AGENTS.md + 六条红线 + 四拍 + 打点 + 《中黄经》书魂档 | 2 周 |
| C. 训练闭环 | tutor.py 定制 | 关卡重排、半对判定实现、错题回归 | 2 周 |
| D. 禄命辅助 | 6–8 张卡 | `90-禄命辅助/` 内容工程 | 1–2 周 |
| E. 其余书魂 | 5 部宋本 + 3 部唐本佐证 | 每档五段 | 3 周 |

### 10.2 MVP（A + B，4 周）

- 《中黄经》一部书跑通完整四拍循环
- 在 5–10 条子平诱导测试用例上第六条红线全部 reject
- 书魂 profile 切换机制可稳定复现
- P0 后作者做一次全对基线体检，>5% 错则回补

### 10.3 回滚

vault 与 AGENTS.md 均纳入 Git 私仓，Obsidian Git 插件 auto commit。任何配置变更以 revert commit 回滚。子项目 C–E 未落地时不影响 MVP。

### 10.4 Testing

- 排盘器：18 项底本回归 + 164 则南宋课例
- 第六红线：5–10 条子平诱导测试用例
- 打点规则：`retro_selftest.py` 47 项边界用例（继承 liuren-classics-lab）
- 书魂串戏：3–5 条诱导跨书发言用例，验证 `70-待查/` 挂号行为

## 11. Risks（Pre-mortem）

假设六个月后系统失败，可能的原因：

1. **书魂档内容空洞**——书魂五段流于套话，导致解读同质化。**指标**：连续三节 R5 命中「同一概念重复追问」。**缓解**：每档五段需引用至少 2 处该书原文，MVP 阶段人工评审。
2. **DeepSeek 对子平约束的遵守不稳定**——尤其在长会话末尾。**指标**：手工抽查 20 条断辞发现 > 1 处子平义项。**缓解**：每 5 轮插入一次红线自检 turn；`retro.py --close` 自动检查。
3. **排盘器口径与宋本某处冲突**——底本自相矛盾时半对◐可能压制人的思考。**指标**：L2 连续 3 轮通关但演练拍作者无异议提出。**缓解**：半对触发时强制展开两说依据。
4. **导读七件套流于形式**——档位卡对短口诀给长导读的问题重现。**指标**：单节 R12「导读不足」≥ 2 次或 R14 超时。**缓解**：R12/R13/R14 命中改模板而非多讲一遍。
5. **跨书校勘失控**——复盘官独立会话摘要不足以承载多书上下文。**指标**：`50-校读笔记/` 里对校矩阵条目 > 20 处 TODO 未闭合。**缓解**：一次校勘限 3 部书；超出拆多轮。
6. **fork 上游断裂**——`liuren-classics-lab` 主分支不再维护或 breaking change。**指标**：`--check` 因上游脚本变动失败。**缓解**：pin 到具体 commit，年度评估同步。
